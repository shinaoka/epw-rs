## EPW（QE 7.6，EPW 6.1）

### 1. `fila2f` で実行するとゼロ除算で止まる（確認済み，優先度：中）

- **場所：** `EPW/src/supercond.f90:104`
- **内容：** `IF (eliashberg .AND. (MOD(nkf1, nqf1) /= 0 ...) .AND. (fila2f == ' '))` は Fortran では短絡評価されません．そのため `fila2f` を指定していても `MOD(nkf1, nqf1)` が評価されます．入力に `nqf1` などを書かないと既定値 0 になり，整数のゼロ除算（SIGFPE）で止まります．同じ形の条件が 102 行にもあります．
- **再現：** α²F のファイルだけで等方的な Eliashberg 方程式を解く入力（`tests/fixtures/mgb2_epw_super/iso/fsr/iso_fsr.in` から k と q のメッシュを消したもの）．
- **修正案：** `IF (fila2f == ' ') THEN` で外側を分ける．

### 2. `eps_cut_ir` が F と G₀ の行にかからない（コード読みのみ，優先度：中）

- **場所：** `EPW/src/supercond_aniso.f90:2826-2858`（Coulomb 版では 3350 行付近にも同じ形）
- **内容：** IR 係数の雑音カットのループは `jx2 = 1..jx` です．しかし係数の配列 `ir_gl_d(3*siz_ir, size)` は，G の常伝導の部分，F（異常項），G₀ の 3 つのブロックをオフセット `0`，`siz_ir`，`2*siz_ir` で並べています．そのため切られるのは最初のブロックと核だけで，F と G₀ は切られません．オフセットの付け忘れの可能性があります．
- **影響：** 未測定です．既定値の `eps_cut_ir = 1e-5` で常に有効です．

### 3. IR の基底サイズが奇数のとき，最後の係数が足されない（影響を確認済み，優先度：低）

- **場所：** `EPW/src/utilities/sparse_ir.f90:682-684`，`1061-1063`，`1580-1603`，`1673-1726`
- **内容：** `evaluate_matsubara_f/b` は，基底の列を偶奇に分けるときに `n/2` を使います．同梱の IR オブジェクト（size = 61）では，最後の列（l = 60）が足されません．`fit_*` と `evaluate_tau` はすべての列を使います．
- **影響：** MgB₂ の異方的 FBW（20 K）で，epw-rs 側でこの扱いを再現すると EPW との Δ の差が最大値比で 1.6e-5 から 1.1e-5 に縮みました．つまりこの扱いで結果が 5e-6 程度変わります．ε = 1e-6 の基底の精度と同程度です．

### 4. FBW の自由エネルギーの Z_N（確認済み，優先度：低，要議論）

- **場所：** `EPW/src/supercond_iso.f90` の `sum_eliashberg_iso_iaxis`（FBW の分岐）
- **内容：** 常伝導の Z_N を `1 + T Σ K⁻/ω` と計算しています．FSR の分岐は `1 + πT Σ K⁻/ω` です．
  - EPW が出す FBW の自由エネルギーは，π のない Z_N を FSR の Bardeen–Stephen の式に入れたものと一致します（`crates/eliashberg/tests/mgb2_isotropic.rs` で確認）．
  - π を付けると MgB₂ の 20 K で正になります．
  - ただし FSR の式を FBW にそのまま使うこと自体が近似（χ とエネルギー積分を無視）なので，バグと断定はできません．FBW での自由エネルギーの定義を確認する問い合わせが適切です．

### 5. H(k) の Hermite 化が経路によって違う（確認済み，優先度：低）

- **場所：** `EPW/src/wannier2bloch.f90` の `hamwan2bloch`（(H + H†)/2 を対角化）と `hamwan2bloch_batch`（Hermite 化せず `ZHEEVD('L')`）
- **内容：** E_F と Fermi 窓の計算と q ループで，H(k) の扱いが違います．
- **影響：** Pb の fixture では H(R) が H(−R)† と 2.8e-17 Ry で一致し，固有値の差は 0 でした．H(R) が Hermite でないデータでだけ差が出ます．整合性の指摘にとどまります．

### 6. `linewidth.phself` は 2γ を書く（確認済み，優先度：低，文書）

- **内容：** 標準出力の `gamma___` は γ ですが，`linewidth.phself` の値はその 2 倍です．ファイルの見出しは「Phonon linewidth (meV)」で，半値幅か全幅かが書かれていません．見出しに明記するとよいと思います．

## EPW の fork（`gitlab.com/h-m0r1/q-e_mine`，sparse-ir-rs 版）

### 7. μ* の項の τ = 0⁺ が近似になっている（コード読みのみ，優先度：中）

- **場所：** `EPW/src/supercond_aniso.f90` の 3600〜3630 行付近（`__USE_LIBSPARSEIR` の分岐）
- **内容：** upstream の IR オブジェクトは τ = 0 と β の端点を含むので，F(τ = 0⁺) を厳密に使えます．sparse-ir-rs の既定の τ 点（[−β/2, β/2]）は端点を含まないので，fork は「最初の正の τ 点」（添字 `ntau_f/2 + 1`）で代用しています．
- **修正案：** 基底関数を τ = +0 で評価する（`evaluate_tau` に 0.0 を渡す）．epw-rs ではこの方法を使っています．

### 8. その他（コード読みのみ，優先度：低）

- `supercond.f90:1796` に `WRITE(1000+mpime,*) wsn(iw)` が残っていて，`fort.1000+rank` を書き出します．
- `EPW/README_sparse_ir.md` が古い内容です（FetchContent での取得と，古い `init_ir` のシグネチャ）．
- sparse-ir-rs の版が上がると τ 点や松原点が変わり得ます．EPW の結果を再現するには，点を固定する手段（ファイルからの読み込みなど）があると安全です．

## tenferro-rs（0.7.1）

### 9. 多項 einsum の結果が呼び出しごとに最後のビットで変わる（確認済み，優先度：中）

- **内容：** 同じ入力で 4 項の einsum `"amkq,abuqk,bnk,uvq->mnkvq"`（複素数）を 20 回呼ぶと，最後のビットの異なる結果が 4 通り出ました．2 項ずつ明示的に縮約すると毎回同じです．縮約経路の選び方が呼び出しごとに変わると推定しています（未確認）．3 項の `"x,xv,xv->v"`（実数）でも同様の非決定性が見られました．
- **影響：** 分散計算でランク数によらずビット単位で同じ結果を出したいときに問題になります．epw-rs では 2 項ずつの縮約で回避しています．
- **報告に添える情報：** 再現コード（`wannier-interp` の `vertex_to_bloch` の旧版），入力の形，CPU のスレッド数．

### 10. スレッド数で結果が変わる（確認済み，優先度：低，文書）

- スレッド数を固定すれば毎回同じですが，スレッド数を変えると最後のビットが変わります．並列での縮約の分割としては自然ですが，再現性の保証の範囲を文書に書いてあるとよいと思います．

### 11. README の例と 0.7.1 の API の差（確認済み，優先度：低，文書）

- README とエージェント向けの文書（`llms.txt`，skill）は `backend.with_backend_session(...)??` と書いています．crates.io の 0.7.1 では，`with_backend_session` がコールバックの戻り値をそのまま返すので，`?` 1 つになります．main とリリース版の差の可能性があります．

## sparse-ir（文書）

### 12. 既定の τ 点の範囲が実装によって違う（確認済み，優先度：低）

- v2 のチュートリアルの「Notation and conventions」は，既定の τ 点が (0, β) にあると書いています（Python と Julia の実装）．sparse-ir-rs（0.7.2 と 0.13.0 で確認）は [−β/2, β/2] を返します．どちらも正しく動きますが，τ = 0⁺ の値や G(−τ) を使う利用者には，実装ごとの違いを明記しておくと安全です．
